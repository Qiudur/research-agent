此轮暴露了评分稳健性问题：Adult Income 的 dev 参考 AUC 差只有 **0.001023**，默认解的 holdout 原始 AUC 为 0.927388，按固定 dev 基线与上限归一化后为 **-2.5303**。负分是协议的真实输出，不应改写或截断原始得分；但旧 C 选择器直接用负的“分数/成本”排序，会让增加花费看似提高效率。本轮原始 `self_research_report.json` 因此保留旧的负比率与选择结果。修复后的策略仅在排序时以 `max(平均分, 0)/花费` 作效率项；非正分并列时先比平均分，再比低成本。本轮在修正策略下仍选择候选，因为 -0.4033 高于 -0.6884，**理由是质量更高，而非效率胜出**。

Adult Income 的微小 dev 参考差使归一化值对跨拆分波动高度敏感；这两题三遍不足以证明迁移优势。候选不推广到正式验证/考试。后续应在 practice 内复核弱 gap 题的校准与排名稳健性，再决定题库冻结和一次性正式评估。
