# 真实模型三路并发 dev 基准

日期：2026-11-14。此页只比较两道练习题上默认配置重复三遍的墙钟，属于真实模型调用、TEST token 记账的 dev 观察，不是正式验证或考试。

## 协议与证据

- 新并发 campaign：runs/token-parallel-default-20261114-081627-fb54/；代码提交 32452a8；模型 qwen3.5-27b；运行 scripts.run_token_self_research 的 --default-only 模式，max_workers=3，不执行提案或候选。
- 两题为 spd-membership-filter、tab-german-credit；每题预算 40,000 个四桶合计 token、每次调用前预留 12,000 token、题包墙钟上限 1,800 秒。三遍各用独立运行和库，单遍内部题目顺序不变；真实沙箱执行与评分在本进程串行。
- 新运行的 protocol.json、summary.json、audit.json 及 project/runs/ 下三份报告、逐题账本、单次 holdout 与重放文件为原始证据。audit.json 机器核验了 3 份报告、6 个任务：四桶 token 之和与账本相等，合计 156,103；6/6 每题唯一一次 holdout，6/6 最佳节点来源完整且重放通过，6/6 任务均低于 40,000 token。
- 对照为 runs/token-self-research-20261114-055221-3c2f/ 的前三次默认配置运行；旧代码提交 13ad7d0，自研究默认串行执行。只取默认组，排除之后的提案调用与候选组。两边模型、两道题及其源哈希、默认配置 SHA256、TEST 价目 SHA256 相同。

## 观测结果

| 默认配置三遍、共 6 个任务 | 新三路并发 | 旧串行 |
|---|---:|---:|
| 墙钟 | 460.778 秒 | 约 1,318.138 秒 |
| 任务 token 合计 | 156,103 | 159,616 |
| 每遍两题平均 token | 52,034 | 53,205 |
| 平均 holdout 归一化分数 | 0.960217 | 1.028183 |

新运行墙钟由 summary.json 的 started_utc、ended_utc 与 elapsed_seconds 给出。旧运行没有同口径的 campaign 计时字段；约 1,318.138 秒是从首个默认 run 名的 05:52:21 UTC 到第三份默认报告修改时间 06:14:19.138 UTC 估算。因此本次观察到约 **2.86 倍**墙钟比值，但不能当成受控、可重复的加速倍数。分数与 token 差异也不能归因于并发。

两次代码提交不同，模型输出有随机性，网关负载和评分机器环境也未固定；旧墙钟还是文件时间估算。TEST 价目的单位等于报告的 token 数，不代表人民币、美元或官方比赛价格。不同 campaign 或队友在同一机器上运行时没有跨进程评分串行保证；表格评分与提速脚本会争用 CPU、扰动计时。后续若比较稳定吞吐，应重复相同版本的串行与并发配对实验，并隔离评分机器或集中评分。正式验证、考试及四线效果比较均尚未执行。
