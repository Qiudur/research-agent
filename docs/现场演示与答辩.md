# 现场演示与答辩提纲

本文件是可执行提纲，不是正式成绩报告。正式模型考试、录屏和最终数字尚待比赛提供模型、价格、预算及凭据；不得把 TEST-only 联调图或脚本角色的结果剪入正式效果展示。

## 正式证据入口

1. 使用 `evaluation.cli figures` 从已完成且准入通过的正式批次生成 `study.html` 和同名 `study.json`，并提供 `--auto-study-dir`。出图过程会复核批次封存源、12 份考试账本、自研究全部成本、胜出配置哈希与三遍研究版 manifest。
2. 打开 `study.json`，确认 `phase=exam`、`test_only=false`、`currency` 为比赛币种、`admission.claim=admitted`。四条线每条恰有三遍运行。把 `comparisons.*.claim` 原样写入答辩稿；`no_clear_difference` 就写“未看出明确差别”。
3. 只有 `breakeven.eligible=true` 且 `breakeven.tasks` 有值时，才报告回本题数。逐题金额、得分和耗时在 `task_rows` 中，每行的 `run_id`、`task_id`、`task_end_seq` 可定位到对应账本。

## 两分钟讲述顺序

- **问题**：给同一个云端模型研究任务，目标是尽量用少的花费和时间取得可验证的效果。
- **方法**：代码规则调度实验树和预算；规划、执行、诊断、总结按角色分档；B 沙箱独立检验正确性、速度或 AUC；C 为每次模型调用分四桶记价。
- **学习**：练习题累积有证据的能力库，自动自研究只用练习题搜索配置和提示词；验证题的三遍配对准入决定研究版能否进入考试，考试库冻结。
- **结果**：展示正式 `study.html` 的四线三遍范围、逐题走势和账本引用，按 `study.json` 的判定原样解释收益、波动、花费及回本点。若没有显著优势，直接说明。
- **防作弊**：展示 Bank Marketing 的 `duration` 禁用规则和推断缺列、提速止损题，以及仅 C 能触发的一次性 holdout 门禁；不要展示考试隐藏数据。

## 分屏与录屏

正式考试结束后，从已完成的报告中选同一提速任务的空库和练过库运行，记录两个 run ID 及其 `task_end_seq`，再运行：

    .venv/bin/python -m dashboard.serve --run-dir runs/<空库run_id> --other-run-dir runs/<练过库run_id> --port 8765

浏览器打开本机服务地址。左侧空库，右侧练过库；每秒刷新一次。现场若重新运行任务，只能标为演示，不能写回正式考试报告。录屏前确认画面与解说均未露出 API Key、隐藏标签、候选源码中的私人路径；录屏文件和正式运行目录留在本机，不提交到 Git。

## 待正式数据后补入

- 模型名、币种与价格表 SHA256、题库版本、代码提交 SHA。
- 三项配对比较的 `claim`、平均分差及三遍范围；各配置平均成本和回本判断。
- 同一任务的左右分屏 run ID、正式报告中的证据定位和录屏文件名。

这些字段只能从正式账本和自动报告摘录；不能用 TEST 结果填充。
