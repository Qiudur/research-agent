# 真实模型自动自研究 dev 试验

日期：2026-11-14。证据目录：`runs/token-self-research-20261114-051022-b187/`；源代码提交：`5b3e191`。此试验只使用两道 practice 题的隔离副本，不是正式验证、考试或现金成本实验。

## 预设配置

- 模型：可本地部署的 `qwen3.5-27b`，通过授权网关实际调用；默认配置为 `config/agent_token_pilot_v2.json`。
- 题目：`spd-membership-filter` 与 `tab-german-credit`。每题 40,000 四桶合计 token，常规扩展阈值 90%，每次调用前预留 12,000 token；本自研究副本沿用题包墙钟 **1,800 秒**，请求输出上限 2,048。独立 token 试点脚本另设 900 秒，不能混作本次协议。
- C 自动自研究：默认配置先重复三遍；模型提出一轮受限候选，候选也重复三遍。每遍均运行两题，并各自完成唯一一次 holdout。
- 账本币种是 `TEST`，此副本四类价格都设为每 token 1 TEST 单位、`unit_tokens=1`；因此数字恰等于网关返回的 token 数，却不是人民币、美元或官方比赛价格。原 `tasks/`、`config/prices.json` 和正式题库均未改动。

## 实测结果

| 配置 | 三遍平均 holdout 归一化分数 | 每遍两题平均 token | 总任务 token |
|---|---:|---:|---:|
| 默认 v2 | 0.9841 | 40,613 | 121,840 |
| 自动候选 `auto-01` | 0.9190 | 51,505 | 154,516 |

提案调用另花 1,597 token，整次自研究共花 **277,953 token**。候选把 diagnoser 推理档从 medium 降为 low，将 plateau_nodes 从 5 降为 4、explore_every 从 4 提到 5、query_k 从 8 降到 6，并在角色提示词后追加节省探索成本的策略。候选并未达到目的：平均分低约 0.0651，平均每遍多花约 10,892 token；按分数/token 的描述性比率也低约 27%。三遍样本和提速计时噪声不足以做显著性断言。

C 的选择机制会保存最佳**生成**候选供后续准入，而不把默认配置伪装成新候选；因此报告里 `selection.candidate=auto-01`，同时明确 `beats_default_on_practice=false`。本轮**不推广**该候选，也不打开正式验证或考试。

## 审计与问题

- 一次提案、六次完整运行、十二次任务收尾都已记录；十二题各只有一次 holdout，实耗均未突破单题 40,000 token。所有六份报告的任务费用与总账、提案账本之和对齐；候选配置 SHA256 已复核。
- 十二个最佳节点的封存来源与库快照哈希均验证通过；其中十一项重放评分落在容差内。默认版第三遍的提速题第一次重放从 dev 1.0799 变为 0.9743，差 0.1056，略超该次 0.0909 容差；代码、种子和来源哈希一致，记为真实计时波动，不抹去这条失败记录。
- 候选第一、二遍在提速题分别做了大量额外探索，花 30,048 和 28,034 token；默认版三遍该题仅花 6,052、4,616、15,730 token。提案者只看到配置级汇总，未看到逐题成本与波动，削减探索深度的建议没有解决实际损耗。
- 可离线看板已从候选第三遍的真实账本导出到本次证据目录的 `dashboard-final-candidate.html`，页面保留 TEST 价目标记。

第二轮只在练习题上改进提案输入：已在 C 的提案载荷加入各题三遍分数区间、花费区间、角色成本、实验次数、停止原因和基线胜出次数，让模型看到哪道题浪费预算；默认版和最近两名候选的逐题摘要始终可见。正式四线比较仍受题库难度、真实价格或明确 token 计价规则及一次性验证/考试准备约束。

## 第二轮：逐题证据提案

证据目录：`runs/token-self-research-20261114-055221-3c2f/`；源代码提交：`13ad7d0`。沿用相同的两道 practice 题、每题 40,000 token、12,000 token 请求预留和三遍对照。两道原题的 `budget.wall_seconds` 均为 **1,800 秒**；本轮副本未改该字段。本轮 C 提案输入已包含第一轮发现缺少的逐题波动和成本证据。

| 配置 | 三遍平均 holdout 归一化分数 | 每遍两题平均 token | 三遍任务 token |
|---|---:|---:|---:|
| 默认 v2 | 1.0282 | 53,205 | 159,616 |
| 自动候选 `auto-01` | 1.0059 | 34,859 | 104,578 |

候选将 planner 从 medium 调至 high、executor 从 low 调至 medium、diagnoser 从 medium 调至 low，并调整预算进度阈值、探索频率和检索条数及角色提示词。它的平均分低 0.0223（约 2.2%），每遍少花 18,346 token（约 34.5%）。提案调用花 2,909 token；全轮任务花 264,194 token，总研究花 **267,103 token**。C 按包含提案开销的分数/token 排序，候选描述性比率高约 45.3%，因此 `selection.beats_default_on_practice=true`；这只表示练习题上的效率指标胜出，**不表示分数不降或已通过验证准入**。三遍配对中候选只在第三遍分数超过默认，German Credit 候选分数跨 0.8501–1.1632，当前不推广到正式流程。

审计了六份报告、十二个任务收尾和各自唯一一次 holdout：每题实际 token 均不超过 40,000，四桶 token、任务账本、提案账本与总额对齐，题包及候选配置/提示词 SHA256 一致。十二个最佳节点的封存来源完整；十一项 dev 重放分数在容差内。候选第二遍提速节点首次重放从 1.2248 降至 0.9779，复测为 0.9919，均超出 0.1755 容差，两个失败记录保留在原 run 的 `replays/`。提速分数对计时敏感，且本轮中途并行跑过测试套件，可能干扰计时；不能将这三遍视为稳定的效果证明。候选第三遍账本看板已导出到证据目录的 `dashboard-final-candidate.html`。

已在两道未参与提案的 practice 题上完成跨题迁移复评，候选分数改善但成本上升；详见 `真实模型迁移复评.md`。正式验证和考试尚未启动。当前脚本会把**今后**自研究副本的逐题实际墙钟限制写入 `protocol.json`，本轮既有协议文件仍保持原始证据不追改。
