## 每人先做

1. 各自克隆仓库或建立独立 worktree，创建姓名加任务名的独立分支；不要在同一工作目录改文件。先记录 git rev-parse HEAD 和 git status --short。
2. 在 macOS、Python 3.11 和 sandbox-exec 可用的环境安装依赖并跑基线测试：

       python3.11 -m venv .venv
       .venv/bin/python -m pip install -e '.[llm,tabular,speedup]'
       .venv/bin/python -m unittest discover -s tests -q
       .venv/bin/python -m unittest discover -s skill_layer/tests -q
       .venv/bin/python -m unittest discover -s dashboard/tests -q

3. 只在自己的分支提交改动。交付时附提交 SHA、运行命令及退出码、任务/配置 SHA、逐题结果、失败记录和运行目录；不要只报平均数。

## 共享资源与合并边界

- 每人使用独立分支、运行目录和凭据注入环境。密钥不得进入仓库、命令历史、日志、报告或聊天转发；TEST token 单位不是现金价格。
- 不要让不同 campaign 在同一评分 Mac 上并跑：现有锁只覆盖单次批次，表格评分与提速脚本会争 CPU，改变计时和分数。若分机器跑，先保持相同代码提交、题包和模型配置，并记录机器差异；成本校准可合并 token 数据，速度分数不可直接跨机器混算。
- 队友不要修改正式 config/prices.json、tasks/bank.json 的冻结标志或正式预算，不要启动 validation/exam、正式 batch、一次性准入，也不要写 runs/*attempt.json。这些由总指挥在代码和证据合并后统一执行。
- 朴素成本校准入口已经提交并通过 7 项定向测试、真实沙箱 dev 联调；总指挥正在独立 worktree 跑 12 道提速题。队友 2 如有另一台 macOS 评分机，可在洁净的独立 clone 上运行表格 12 题：

       .venv/bin/python -m scripts.calibrate_naive_tokens --scenario tabular --repetitions 3 --workers 3

  若只有同一台 Mac，先做静态/数据审计，等提速校准结束再评分。此命令只使用 dev、每题自选 40,000 token 预算，结果在 runs/naive-token-calibration-*/summary.json；交付时连同 protocol.json、逐次账本和提交 SHA 一起给总指挥。失败记录不自动重试，不能从 TEST token 单位推断现金价格。不要再跑提速组，以免重复消耗。
- 总指挥负责解决分支冲突、核对 SHA 与账本、冻结版本、运行唯一一次验证/考试，并如实报告未通过准入或无显著优势的结果。
