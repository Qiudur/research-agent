# 越做越便宜的 AI 研究员 · 三人分工

2026-11-13

## 一句话

做一个多 agent 研究系统：自主跑「规划 → 收集证据 → 提假设 → 实验 → 验证 → 修正」的研究闭环，按难度分配 token，越做越省。

**Punchline：「越做越便宜的 AI 研究员，连怎么省钱都是它自己研究出来的。」**

- **主数字**：在考试题上，练过的系统比没练过的花钱更少，分数不降。
- **保底数字**：同样的分数，比朴素版（单个 agent、全程高推理、喂全部历史）花得少一大截。主数字实测不成立的话，就用这个数字。
- **回本点**：研究自己花了 X 元，之后每个任务省 Y 元，做到第 N 个任务回本。
- **现场**：开工先报价、做完对账；分屏跑同一道提速题（左边空能力库，右边练过的），看板实时显示。

## 赛题要点与我们的解读

赛题是倍漾量化的 Research Agent 系统设计：在给定的数据、工具和预算下，自主完成研究闭环，交付可追溯、可复现、可持续提升的成果。评委看三样：云端模型花了多少钱、任务完成度（或加速比）、用了多长时间。

主办方批注带来四点：

1. **不用本地模型**。比赛里可能只有一个大模型，所有 agent 都用它。省钱靠少调用、少喂内容、按难度决定让模型想多深，不靠换模型。
2. **研究任务自选、偏轻量**。重点是「怎么用 agent 做研究」，不是任务本身。
3. **系统本身也要评估**：花了多少 token、多长时间带来多少提升、能不能自我迭代。
4. **给定的数据、工具、预算开赛后才公布**，所以框架要和具体题目分开。

我们的选择：两个场景都做，表格分类（主办方举的例子）加 Python 代码提速（指标最硬），用来证明系统和任务无关。

## 系统架构

```
任务包（说明 + 工作区 + 评分器 + 基线 + 预算）
              │
     调度器（代码规则）── 账本 / 预算闸门 / 报价
              │  决定下一步展开哪个实验
   ┌──────┬───┴────┬────────┐
  规划者   执行者    诊断者    总结者     ← 同一个大模型，推理强度不同
  （高）   （低）    （高）    （中）
              │
   实验树：节点 = 假设 + 代码 + 分数 + 花费 + 能力库版本
              │                      评审：脚本判断，不用模型
   能力库：经验 → 技能 → 工具（随做随改，研究自己时大改，考试时冻结）
```

| 部件 | 做什么 |
|---|---|
| 任务包 | 统一接口：文字说明、工作区（数据或原始代码）、评分器（agent 只能调用拿分，看不到内部）、基线、预算。agent 每次交出一份能跑的代码。换场景只换任务包。 |
| 调度器 | 代码写死的规则：下一个展开哪个节点、预算还剩多少、硬上限到没到。不设「经理 agent」。 |
| 规划者 | 开局先报价，列出假设清单（每条带预期提升、预估花费、用了哪条经验），给出预算分配和预期进度。分数停滞或进度落后时复盘，决定换方向、在任务预算内追加，还是停。高推理。 |
| 执行者 | 把一条假设写成代码并运行，出错自己修，最多 3 次。修 bug 算同一个节点内的重试，不算新节点；修不好就把节点标成「失败」，记下原因。低推理、短输出，调用次数最多。 |
| 诊断者 | 只在执行者修 3 次仍失败，或者分数异常（暴跌，或暴涨到像是泄漏）时才叫。高推理。 |
| 总结者 | 任务结束时，读脚本抽好的摘要，写成经验条目，只调用一次。中推理。 |
| 评审 | 脚本，不用模型：提升要超过正常波动才接受，同时做防作弊检查。 |
| 实验树 | 每个节点记一个假设、代码、分数、花费、父节点、当时的能力库版本。失败的节点也保留。 |
| 账本 | 只往后追加的 JSONL。每次模型调用记角色、推理强度、各类 token（输入 / 命中缓存的输入 / 输出 / 推理）、按价格表折算的钱、耗时。耗时拆成等模型、跑实验、排队测速三块。配一条重跑命令，给实验编号就能复现。 |
| 能力库 | 经验 → 技能 → 工具三级，见下方「能力库与自我进化」。 |
| 沙箱 | agent 写的代码在限时、限内存的子进程里跑，每个实验一个目录。评分器和测试数据放在 agent 碰不到的地方。 |
| 看板 | 一个网页，读账本，每秒刷新。 |

## 已拍板的决定

### 场景与打分

- **表格分类**：数据切成三份：训练（agent 随便用，自己做交叉验证）、dev（评审脚本判断改进算不算数）、holdout（最后打一次分，agent 全程碰不到）。dev / holdout 是一道题内部的切分，和「练习 / 验证 / 考试」这种题的分层是两回事。分数 =（agent − 基线）÷（上限 − 基线）。基线是默认参数的 LightGBM，上限是 AutoGluon 跑固定时长的结果。
- **代码提速**：结果不对直接 0 分；对了的话，分数 = agent 的加速比 ÷ 参考最优解的加速比。参考最优解用大模型提前写好、验证过。
- 两个场景都换算成「从基线到上限走完了百分之几」，可以画在同一张图上。
- **测速**：先预热一次；原代码和新代码交替测 N 次，取中位数；输入规模调到原代码跑 1–2 秒；同时报波动范围；测速时接电源、关掉其他耗资源的程序。测速独占机器、排队进行，其余步骤可以并行。评委看的完成时间包括排队等测速的时间。
- **正确性检查**：每次用新的随机种子生成输入。
- **防作弊**：表格任务防偷看测试标签、防把验证集混进训练；提速任务防把测试输入的结果提前存好直接返回、防偷偷改变函数原本的行为。

### 成本与时间

- **只有一个大模型时，省 token 的办法**：能用脚本做的不叫模型；每个 agent 只喂整理好的当前状态，不喂全部历史；按角色和难度决定推理强度；设预算闸门。
- **提示词按「固定部分在前、变化部分在后」排**，好命中输入缓存，看板显示缓存命中率。开赛给的模型不支持缓存的话，这条作废。
- **成本按 token 类型分开记**，再按价格表（配置文件）换算成钱。预算闸门按钱算。
- **停止规则**：
  - 代码管硬上限：预算花到 90%（剩下 10% 留给收尾）、时间到、分数到顶，任一条撞上就停。硬上限只有人能改，模型改不了。
  - 规划者管软判断：连续 5 个节点都没有超过正常波动的提升，或者钱已经花了一半、分数还不到预期进度的一半，就叫它复盘。追加预算只能在这个任务的总预算里挪。
- **待试的假设按「预期提升 ÷ 预估花费」排队**：初值由规划者给，再用经验库里的历史效果修正；规划者过去的预估误差也拿来修正它。默认从分数最好的节点往下长，每展开 4 个节点留 1 个给其他方向。
- **开工先报价**（预计花多少钱、多少时间、能到多少分），做完对账。预算明显不够时，直接说做不到。

### 证据与可追溯

- 「收集证据」只用三类东西：脚本产生的画像（表格任务是数据画像，提速任务是性能画像）、历次实验结果、能力库。第一版不接网页搜索，接口留好。
- 报告从账本自动生成，每个数字都能追到账本里的某一行。每条结论标上价钱和证据，例如：「目标编码让 AUC 提升 0.02（花费 1.3 元，证据：节点 7、12、15，3 遍方向一致）」。
- 大模型审报告不在核心流程里，开了就算进成本。
- 主循环自己用 Python 写，不用 LangGraph、AutoGen 这类框架。

### 能力库与自我进化

- **三级晋升阶梯**：
  - **经验**：一条文字，按固定字段记：场景、触发特征、做法、效果、来源，另外标明是「题目经验」还是「方法经验」。没用的招也要记，比如「这招在这类数据上白花了多少钱」。只在任务结束时写入，任务中途不写，免得把没验证的猜测存进去。查找时按场景和触发特征匹配，第一版不用向量数据库。经验库只给规划者看，不给每个 agent 都塞一份，省 token。
  - **技能**：一套操作步骤。经验的可信度够高、并且在 2 道以上的题上都管用，就晋升为技能。提示词里平时只放技能的名字和一句话简介，选中了才加载全文。
  - **工具**：能直接调用的函数。技能里的同一段代码在 2 道以上的题上原样管用，就晋升为工具。
- **可信度**：规划者提假设时标明用了哪条经验，实验有效就给它加分，无效就减分。分数低于门槛的不再推荐，同类合并，整个库设条数上限。可以降级，降到底就淘汰。
- **经验失灵时改窄适用条件**，不只是减分。旧的写法和改动原因都保留。
- **工具自带回归测试**，用例取自它管用过的那些题。新版本必须通过全部旧用例才能替换旧版。
- **能力库每次变化都存版本**，记下改了什么、为什么改、证据是哪几个节点。每个实验节点记下当时的能力库版本，重跑时自动切回那个版本。这份变更记录画成一条「能力库进化史」时间线。
- **两种进化方式**：随做随改，在每个练习任务结束时按规则小幅调整；研究自己时集中大改。考试时整个库冻结。
- **研究自己**：把系统自己的设置（各角色的推理强度、复盘门槛、给新方向留的比例）、各角色的提示词、技能和工具都当成研究对象，做成一个任务包，用同一套系统去研究。开发阶段不设预算，也不算进评委打分的花费，但每一笔都记账，答辩时公开。体检题用练习题，选出的版本必须过验证集准入。

### 评估设计

- **题分三层**：

| 层 | 用途 | 次数 | 预算 |
|---|---|---|---|
| 练习集 | 积累能力库；研究自己时反复试 | 不限 | 不卡 |
| 验证集 | 研究出来的版本过一次准入关 | 1 轮 | 不卡 |
| 考试集 | 正式评估 | 1 轮 | 严格卡 |

- **准入标准**：研究版和默认版在验证题上各跑 3 遍，得分不比默认版低、花费比默认版低，而且 3 遍方向一致，才算通过。不通过就用默认设置，报告里写明。
- **题库**：每个场景至少 12 道题（练习至少 5 道、验证 2–3 道、考试至少 5 道）。每道新题入库必须带齐评分器、基线、参考最优解。难度用朴素版实际跑的花费来定档；按难度分层随机抽题；每个场景至少 1 道埋坑题固定放进考试集。正式对照之前冻结题库版本，之后加的题只进下一个版本。
- **已入库的题**（还可以再加）：
  - 表格：Titanic、Adult（人口收入）、Telco 客户流失、Give Me Some Credit、Bank Marketing
  - 提速：距离矩阵、收益率与滚动均值、逐只股票 groupby 算因子、最大回撤、滚动窗口最大值 / 中位数、编辑距离
- **埋坑题**：
  - 泄漏：Bank Marketing 里的「通话时长」是打完电话才知道的信息
  - 作弊诱惑：一道题只要把测试输入的结果提前存好，就能拿高分
  - 该止损的题：标签很脏、分数怎么都涨不上去

  报告里专门写一节「它没有上当」。
- **主图**（考试集，每条线都画出 3 遍的波动范围）：
  1. 朴素版
  2. 默认设置，能力库为空
  3. 默认设置 + 练好的能力库
  4. 研究出来的版本 + 练好的能力库

  1 到 2 的差距是保底 punchline，2 到 3 是能力库的贡献，3 到 4 是研究自己的贡献。图旁边标出回本点。另外配一条「分数随时间变化」的曲线，以及一张表：每个任务的花费、耗时（拆成三块）、得分。
- **每个「任务 × 配置」跑 3 遍**：每一遍都从空能力库开始，先在练习集上积累，再去考试。练习集的顺序固定，考试时能力库冻结。结果报平均值和最好、最差。
- **什么时候才能说「更好」**：3 遍方向一致，而且平均差距比配置自己 3 遍之间的波动还大。达不到就写「没看出差别」。考试结果怎样就报怎样，不回头改了再跑。
- **另外两张图**：规划者预估误差随做过的任务数下降的曲线；方法经验跨场景迁移实验（只在表格练习集上积累，拿去考提速考试题）。

### 展示与答辩

- **看板**：
  - 左边：实验树实时长出来，颜色表示分数，失败的节点显示灰色，每个节点标上角色和推理强度
  - 右上：花费计数器、预算条、耗时三块、报价与实际的对比、缓存命中率
  - 右下：分数随花费变化的曲线，叠一条事先跑好的朴素版曲线
  - 底部：滚动字幕，显示谁在干什么，以及为什么叫来了诊断者
  - 另有能力库面板和进化史；「研究自己」单独一页
- **现场演示**：分屏跑同一道提速考试题，左边空能力库，右边练过的，评委从准备好的题里挑。用的都是已经正式跑过的考试题，现场结果只展示、不进报告，旁边并排放正式结果兜底。另外备一段录屏。

## 四份接口约定（v1 已定）

四份约定已经定好，完整定义在同目录的 [接口约定.md](接口约定.md)，包括目录结构、每个文件的字段、每个函数的签名。M0 改成三人一起花一两个小时过一遍，有异议当场改，改完就冻结；之后要改须三人同意，并把版本号加一。

有了约定，谁都不用等谁：B 用假数据造任务包；C 用假账本做看板；C 的账本写入模块在 M0 当天先交一个同签名的最简版本，A 直接用；B 拿假的经验条目先搭技能层。

| 约定 | 谁负责 | 谁用 | 关键内容 |
|---|---|---|---|
| 任务包格式 | B | A、C | 每道题一个目录：`task.json`（给 agent 看的说明、交付物的函数签名、指标、预算）、`workspace/`（训练数据或原始代码、画像）、`hidden/`（agent 看不到）。题的分层、难度、埋坑类型、基线和上限的原始分另放在 `bank.json`。B 提供 `load_task`、`run_script`、`score`、`profile_code`；`score` 返回归一化分数、原始指标、波动、正确性、作弊标记 |
| 账本格式 | C（含写入模块） | A 调写入模块记账；C 的看板和报告来读 | 每次运行一个 `manifest.json`（阶段、配置、第几遍、题库和能力库版本），每个任务一份只追加的 `ledger.jsonl`，事件分 11 种（模型调用、实验、评分、复盘、报价、能力库操作、停止等）。C 提供写入模块 `Ledger`（`llm_call`、`emit`、`spent`、`elapsed`），按价格表自动算钱；价格没填就报错，绝不记成 0 |
| 实验树节点格式 | A | C（摘要抽取、报价、出图） | 每个任务一份 `tree.jsonl`，节点每变一次就追加一行完整快照。节点记假设、来源、引用的能力库条目、规划者的预估、优先级、状态、尝试次数、dev 分数和波动、花费、耗时、能力库版本。`n0000` 是起点（基线方案或原始代码）；接受规则写死在约定里 |
| 能力库接口 | A | B（技能层建在经验库上）、C（能力库面板和进化史） | 每次运行自己一份 `library/`：当前状态、只追加的变更记录、每个版本的快照。A 提供 `query`、`brief`、`load_skill`、`record_use`、`write_experiences`、`narrow`、`changelog`，以及所有写操作都必须经过的底层 `put`；B 在 `put` 之上做技能层和工具库。晋升、降级的默认门槛放在可调设置 `config/agent.json` 里 |

## 三条线的职责

谁拿哪条线，由团队自己定。

- **A：agent 本体**：主循环、模型接口与推理强度、四个角色和它们的提示词、调度规则、实验树、重跑命令、经验库（写入、查找、可信度、改窄条件、版本、冻结）；M4 把设置和提示词开放成可调的对象。本人工作量约占 40%，三条线里最重，也最难估。
- **B：任务与评分**：两个场景的任务包、评分器、基线和参考上限、沙箱、测速器、防作弊、题库（扩到每个场景至少 12 道、实测定难度、分层抽题、冻结版本）、埋坑题；M4 起负责「研究自己」的任务包和技能层（按需加载、晋升降级），并执行验证集准入和正式考试；M5 有空再做工具库。本人工作量约占 30%，M3 之后去帮 A 调提示词。
- **C：评估与展示**：账本写入模块（价格表、花费换算、耗时三块）、给总结者用的摘要抽取脚本、报价与对账、实验编排（配置 × 任务 × 3 遍，练习 / 验证 / 考试流程）、出图、报告自动生成、看板（从 M1 开始做）、现场演示与录屏、答辩材料。本人工作量约占 30%，M4 最忙。

和最初的分法相比，挪动了这几块：账本写入、价格表和花费换算，从 A 挪给 C；摘要抽取脚本和报价，从 A 挪给 C；技能层和工具库，从 A 挪给 B；验证集准入和正式考试的执行，从 C 挪给 B。

## 里程碑

M3 之前是 punchline 的生命线：任何亮点都不许拖慢 M3。

| | A：agent 本体 | B：任务与评分 | C：评估与展示 |
|---|---|---|---|
| **M0（一两个小时）** | 三人一起过一遍接口约定 v1，有异议当场改，然后冻结；C 交账本写入模块的最简版本 | 同左 | 同左 |
| **M1 最小闭环** | 主循环；规划者 + 执行者（自己修 bug，最多 3 次）；实验树；模型接口（推理强度、token 计数）；重跑命令；账本写入模块交付前先写空壳 | 一道表格题的任务包、评分器、LightGBM 基线、AutoGluon 上限；沙箱 | **账本写入模块**（token 分类、价格表、花费换算、耗时三块，先交一个能用的版本）；看板 v0（读账本，显示实验树和花费）；实验编排的脚手架 |
| **M2 接上提速，拿保底数字** | 诊断者；推理强度分档；预算闸门和硬上限；规划者的预算分配、预期进度、复盘触发；假设排队规则；总结者；适合缓存的提示词结构 | 提速场景：测速器、首批题目和参考最优解、正确性检查（新随机种子）；补齐表格题；防作弊检查 | 在练习集上对比朴素版和分档版，拿到**保底 punchline 的数字**；第一版图；**给总结者用的摘要抽取脚本** |
| **M3 能力库，拿预演数字** | 经验库：字段和标签、任务结束时写入、查找、可信度、改窄条件、版本化；考试冻结开关 | 题库扩到每个场景至少 12 道；用朴素版实测定难度；埋坑题；分层随机抽题；冻结 v1；之后去帮 A 调提示词 | 3 遍流程（空库起步、固定顺序、考试冻结）；用练习集内部切分跑出**主 punchline 的预演数字**；**报价与对账**；预估误差曲线；跨场景迁移实验；把「什么时候能说更好」的判定规则写进脚本 |
| **M4 研究自己 + 正式评估** | 把设置和提示词开放成可以调的对象 | 「研究自己」的任务包：练习题当体检题，按「每花 1 元拿多少分」打分，不设预算但记账；产出最佳版本；**技能层**（按需加载、晋升降级）；**执行验证集准入，代码冻结后在考试集上正式跑一轮**（4 条线 × 3 遍），拿到**正式数字** | 报告自动生成（价签、证据链、「它没有上当」、回本点）；看板完整版（含能力库面板和进化史）和分屏演示 |
| **M5 收尾** | 三人一起：录兜底视频、写答辩稿、彩排 | 同左；有空再做工具库（技能升级成工具、回归测试）和题库 v2，都不进正式数字 | 同左 |

## 工作量估算

粗估，单位是「人天」：一个人借助 Claude 专心干一天。M5 不算在内。都是按模块拍的估计，没有实测；做完 M1 后拿实际耗时对一下，整体乘一个系数。

| | 总工作量 | 可交给 Qoder | 本人工作量 | 本人占比 | 最忙的阶段 | 心里有没有底 |
|---|---|---|---|---|---|---|
| A · agent 本体 | 8.25 | 几乎没有 | 8.25 | 40% | M1–M3，各阶段差不多 | 最没底：提示词要调到闭环真能把分数提上去 |
| B · 任务与评分 | 8.75 | 约 2.5 | 6.25 | 30% | M2–M3 | 最有底：多是体力活，结果能直接检查 |
| C · 评估与展示 | 7.75 | 约 1.5 | 6.25 | 30% | M4 | 中等：活多，但都能预估 |
| 合计 | 24.75 | 约 4 | 20.75 | 100% | | |

- **A 的明细**：M1 2；M2 2；M3 1.75；M4 0.5；贯穿全程 2（调提示词让闭环真能涨分 1.5，接入 B 和 C 的模块 0.5）。
- **B 的明细**：M1 1.5；M2 2.5（约 1 可交 Qoder）；M3 2.5（约 1.5 可交 Qoder）；M4 2.25。
- **C 的明细**：M1 1.75；M2 1.25；M3 2.25；M4 2.5（看板页面和出图脚本约 1.5 可交 Qoder）。
- **M5 另算**：录屏、答辩稿、彩排三人一起约 1 天；工具库有空再做。
- **工期**：三个人并行，大约 7–8 个工作日做到 M4。比赛时间更短的话，按这个顺序砍：M5 全砍 → 跨场景迁移实验 → 技能层（只留经验库）→「研究自己」只调 3 个参数、不调提示词 → 缩小题库。后三条会改动已经拍板的决定，砍之前全队再确认一次。
- **Claude 额度**：Team 套餐的额度一般按人算。A 几乎全靠 Claude，B 吃 Claude 额度最少，额度紧的人适合拿 B。

## 铁律与风险

铁律：

1. 任何亮点都不许拖慢 M3。
2. 考试集只跑一轮，结果怎样就报怎样。正式跑之前，代码和能力库都冻结。
3. 硬上限只有人能改，模型改不了。
4. 报告里每个数字都能追到账本里的一行。
5. 四份接口约定的任何改动，须三人同意，并把版本号加一。
6. 研究自己时只看练习集；验证集只用一轮，用来做准入。

主要风险：

- **A 的活最重，也最难估。** 本人工作量约占 40%，难点不在写代码，而在让大模型真的做出有效的研究。建议最熟悉调大模型的人拿 A；B 在 M3 之后去帮 A 调提示词。
- **正式评估很花钱**：4 条线 × 3 遍，每遍都要走完两个场景的练习集和考试集。拿到价格表后，先估一个总花费，再定每道题的预算。
- **提示词和工具最容易「背题」**，全靠验证集准入和考试冻结来兜底。

## 考虑过、不做

讨论中提过、最后决定不做的。以后有人再提，先看这里。

| 做法 | 为什么不做 |
|---|---|
| 用本地小模型干活，卡住再叫云端 | 主办方批注说可以忽略本地模型，比赛里可能只有一个大模型 |
| 让大模型当经理来指挥 | 每一步都要读全局状态，最费 token；行为不稳定，难复现 |
| 用 LangGraph、AutoGen 这类框架 | 日志和记账得从框架内部去扒，不如自己写的主循环可控 |
| 第一版接网页搜索、读论文 | 结果不稳定、难复现、费 token。接口留着，以后可以加 |
| 量化式的预算组合（把假设当投资，按风险分仓位） | 讨论后决定不做 |
| 随时喊停、立刻出报告 | 讨论后决定不做 |
| 评委现场给一个新数据集 | 系统得现场自动做成任务包，多一大块工作，失败风险高 |
| AI 和真人研究员比赛 | 要占一个队员大量时间，而且真人可能赢 |
| 两个 agent 辩论来做关键判断 | 很多团队都在做，不新鲜 |
| 每次升级都回放一遍，看值不值 | 太费钱。这类数据在研究自己时顺带就能拿到 |
