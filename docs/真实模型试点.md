# 真实模型 dev token 试点

日期：2026-11-14。比赛未指定模型或题目预算；本轮采用公开可本地部署的 qwen3.5-27b，通过授权 NewAPI 网关调用。网关通知的每日额度单位未核实，不能换算为 token 或现金。所有结果仅是自选预算的练习题 dev 试点，不是正式验证或考试。

## 配置

- 任务：spd-membership-filter 与 tab-mushroom-edibility，两道均属于 practice；复制题包到 runs 下并修改副本预算，原 task.json 保持 budget.money=null。
- 单题预算：40,000 TOKENS；调度器在 90% 即 36,000 token 附近停止常规扩展；每次请求前要求账本余额至少留 5,000 token。墙钟上限 900 秒，请求超时 180 秒，SDK 不自动重试。
- 四桶计量：普通输入、缓存输入、可见输出、推理输出各计 1，unit_tokens=1，currency=TOKENS，test_only=true，manifest.phase=dev。这不代表人民币、美元或网关额度。
- 请求输出上限设为 2,048；实测网关的推理 token 可能超过请求上限，因此 5,000 token 预留和 36,000 阈值都不是绝对账单硬上限。每次实际调用以账本四桶用量为准。
- v1 角色推理档：planner high、executor low、diagnoser high、summarizer medium。v2：medium、low、medium、low，并强化沿用表格基线与归一化分数提示。两个版本的提示词和配置单独存档，旧运行的输入哈希没有改动。
- 凭据只从进程环境读取；模型可见的任务状态只含公开工作区和历史实验摘要。原始模型可见输出留在各运行的 model_responses 目录，供排查格式问题；不含凭据。

## 工程修正与下一步

网关接受了 json_schema 参数却返回其他字段或 Markdown 围栏。现在请求指令显式附 schema，客户端逐字段验证；仅对单个纯 JSON 代码围栏做格式兼容，并保存响应审计。预算预留不足时停止发请求、收束运行中节点、写 budget_cap。15 个表格任务的通用基线注释此前误写成 Bank Marketing，已修正成中性说明，代码行为不变。

下一步在相同练习题复用提速题产生的真实经验条目，核对检索、引用和实际效果；再考虑扩展练习题及固定预算下的朴素版对照。未开始一次性的正式验证或考试。
