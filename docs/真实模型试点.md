# 真实模型 dev token 试点

日期：2026-11-14。比赛未指定模型或题目预算；本轮采用公开可本地部署的 qwen3.5-27b，通过授权 NewAPI 网关调用。网关通知的每日额度单位未核实，不能换算为 token 或现金。所有结果仅是自选预算的练习题 dev 试点，不是正式验证或考试。

## 配置

- 任务：spd-membership-filter 与 tab-mushroom-edibility，两道均属于 practice；复制题包到 runs 下并修改副本预算，原 task.json 保持 budget.money=null。
- 单题预算：40,000 TOKENS；调度器在 90% 即 36,000 token 附近停止常规扩展；每次请求前要求账本余额至少留 5,000 token。墙钟上限 900 秒，请求超时 180 秒，SDK 不自动重试。
- 四桶计量：普通输入、缓存输入、可见输出、推理输出各计 1，unit_tokens=1，currency=TOKENS，test_only=true，manifest.phase=dev。这不代表人民币、美元或网关额度。
- 请求输出上限设为 2,048；实测网关的推理 token 可能超过请求上限，因此 5,000 token 预留和 36,000 阈值都不是绝对账单硬上限。每次实际调用以账本四桶用量为准。
- v1 角色推理档：planner high、executor low、diagnoser high、summarizer medium。v2：medium、low、medium、low，并强化沿用表格基线与归一化分数提示。两个版本的提示词和配置单独存档，旧运行的输入哈希没有改动。
- 凭据只从进程环境读取；模型可见的任务状态只含公开工作区和历史实验摘要。原始模型可见输出留在各运行的 model_responses 目录，供排查格式问题；不含凭据。

## 工程修正与下一步

网关接受了 json_schema 参数却返回其他字段或 Markdown 围栏。现在请求指令显式附 schema，客户端逐字段验证；仅对单个纯 JSON 代码围栏做格式兼容，并保存响应审计。预算预留不足时停止发请求、收束运行中节点、写 budget_cap。15 个表格任务的通用基线注释此前误写成 Bank Marketing，已修正成中性说明，代码行为不变。

跨运行经验复用已在同一道练习题执行：系统从旧库读到 exp-0001，四个候选引用它，其中一个被接受、三个被拒绝；条目可信度由 0.5 降至 0.15，状态降级。该次运行比首次成功的空库运行消耗更多 token（25,455 对 18,055），不能宣称节省或泛化；两次 holdout 也不是配对重复实验。后续规划返回无效 JSON 使该次主循环以 error 停止，但 C 依据已有 stop 和最佳节点完成了唯一一次 holdout、报告与回放封存。代码随后加入回归：此类模型格式错误在未来运行会自动保留最佳节点、写 error 停止并完成 C 收尾，而非抛出中断。

第三道练习题 German Credit 用同一 40,000 token 预算和 v2 配置跑通，频率编码候选在 dev 胜过原始 LightGBM 基线（raw AUC 0.7710 对 0.7267），holdout 正确且无作弊标记。这只是一次运行，holdout 没有配对基线测量，不能给出显著性或总体优势。规划者报价 1,900 token，实际 35,106，严重低估；现已将 C 原有的中位历史误差校准接入批次，同一运行内仅用此前同场景任务的预测/实耗对修正后续报价，单题试点仍保留原始未校准报价。German Credit 和 Australian Credit 原始基线沿用的 Bank Marketing duration 删除语句实际是无操作，已去掉误导性注释和无操作代码；两题 train.csv 都没有名为 duration 的列。

朴素配置的两次对照均采用相同任务、副本预算、模型和 token 计量。German Credit 朴素版单次 dev/holdout 数值高于默认 v2，但两次运行的随机种子和模型采样不同，不能直接认定配置优势。朴素版总结阶段生成了 `triggers:["n0001"]`，原运行因此在已记录 `stop=error` 后中断；原始失败保留在 campaign `failed`，恢复记录单列在 `recovered`。恢复仅封存回放输入并调用 C 的一次性 holdout、run_end 和报告，没有再次调用模型。修复后，A 会按草稿逐条核对当前任务的特征词与证据节点，拒绝原因写入 `experience_rejections.jsonl`；有效草稿仍入库，库版本冲突仍会显式失败。

下一步在固定预算下增加配对重复，并扩大练习题覆盖。未开始一次性的正式验证或考试。
