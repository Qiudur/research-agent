## 候选如何生成

1. 只读 Qwen-only 的三份 run report、30 份 task ledger 和实验树，逐项核对 task_end 成本与总 token。
2. 统计执行失败、连续两个 rejected/failed 节点、分数下降及失败节点。当前证据分别为 3、19、20、12 次，因此升级角色开放 planner、executor、diagnoser；summarizer 固定 Qwen。
3. 触发阈值：executor 连续失败 2 次、planner 连续未改善 2 节点、diagnoser 已触发时分数下降至少 0.1；每题最多 2 次远端调用。配置、基线哈希和 30 份逐题证据写入 config/route_policy_self_evolving.json。这是受限、确定性的自动提案，提案模型调用和 token 为 0。
4. 角色目标：planner 用 gpt-6-astra，executor/diagnoser 用 claude-opus-5-5。只有触发且未达到单题上限才升级；失败请求仍计入上限及账本，不自动回退重试。

## 运行

在本分支目录使用 Python 3.11+ 和 openai Python 包。先执行下列命令，只准备 campaign 和封存候选，不请求模型：

    ./.venv/bin/python -m scripts.run_self_evolving --prepare-only

命令会输出 campaign_dir。然后在用户可见的 Terminal 执行：

    ./.venv/bin/python -m scripts.run_self_evolving --campaign <刚才输出的 campaign_dir>

如未设置 OPENAI_API_KEY，脚本会交互式提示；输入不回显。不要在命令行参数、聊天、日志或仓库中写 key。网关默认地址为 https://ai-gateway.theunifiedcare.com/v1。运行前需确认两个远端模型在该网关可用；脚本自动执行此检查。

正式任务开始前依次对 Qwen、GPT、Claude 做 Responses JSON 小请求，记录每个模型的成功/失败及返回 token；任一失败则不启动十题任务。成功后执行 10 题 × 3 遍，每次模型请求入四桶 token 账本，并附上一条可追溯的路由决定。每题和每次 run 均能对账到报告。

## 比较口径

预先冻结的质量门槛：最多 2 题的平均分比 Qwen-only 下降超过 0.1，且 speedup 和 tabular 各自的题目均分中位数下降不超过 0.1。comparison.json 保留两组逐题三遍原分数、token、远端调用、失败调用与负结果。两组代码提交不同，结果仅作为同一套 practice 题的探索性比较；不能声称同版本配对验证或真实金钱节省。预检 token 另计入研究总 token。
