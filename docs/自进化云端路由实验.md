# 自进化云端调用路由：dev 实验方案

状态：设计已记录，尚未实现多模型路由，尚未调用 Claude API 或 OpenAI API 模型做本方案的实验。本文是对原来“单个大模型、按角色分档”方案的候选扩展，不改写既有试验结果，也不打开一次性的正式验证或考试。

## 问题与口径

研究问题：在相同任务、质量下限和时间预算内，系统能否从练习题证据中学出“何时值得调用更强的云端模型”，从而减少云端调用和总成本？只有同时报告任务效果、云端调用情况、总成本和耗时，才能回答这个问题。

- Qwen3.5-27B 在当前 dev 试点中通过远程 API 调用，只作为未来可本地部署模型的替身。报告须明确“Qwen API 代理本地模型”；其 token、API 耗时和实际费用不得记为零，也不能声称已实测本地 GPU 成本或延迟。
- 本方案的“云端调用”单列 Claude API 或 OpenAI API 模型的真实请求。使用 OpenAI SDK 访问 Qwen 兼容网关，不等于调用了 ChatGPT 或 OpenAI API 模型。
- 先只选择一个云端模型和一套已核实的价格，避免模型差异与路由差异混在一起。若赛题指定模型、API 或计费口径，以主办方原文为准；当前仓库没有可核验的官方完整评分细则。

## 最小可检验假设

1. Qwen-only 是低云端调用基线；云端模型全程承担四角色是效果/成本参照，先在少量 practice 题上测量，不作为默认方案。
2. 固定规则路由是机制基线：执行代码连续失败、实验分数异常、或规划者无可执行假设时，才把下一次相应角色调用升级到云端模型。
3. 自进化路由只根据 practice 证据调整升级角色、触发阈值和单题云端调用上限；比较其相对固定规则的质量、真实云端费用、全部模型费用和墙钟。

路由不读取隐藏标签、正式验证/考试成绩或评分器内部；不把模型自报“信心”单独当成升级依据。首版优先使用已可审计的失败次数、分数停滞、异常标记、任务画像、剩余预算和历史同类任务结果。

## 练习阶段闭环

1. 在隔离的 dev/practice 副本上冻结任务包、代码、提示词、模型版本和价格表哈希；每组使用相同题目顺序、预算及评分环境。提速评分避免与其他 campaign 在同一机器并跑。
2. 为每个策略记录路由决策：可见状态摘要、触发原因、角色、原拟模型、实际模型、预算余额、请求结果。失败请求及可得用量照样入账。
3. 至少做三遍独立重复，并按题目展示分数、云端调用次数及分角色占比、云端费用、Qwen 代理费用、总费用和墙钟的范围；不能只报均值或挑最好的一遍。
4. 自研究只能在 practice 上生成受限的新路由配置。每个候选先做低成本筛选，再对有希望的候选跑完整重复；筛选与提案费用也计入研究总成本。
5. 质量必须先达到预先声明的下限，再在合格候选中比较云端费用、总费用与耗时。不能仅以分数/token 或云端调用数最少排序，尤其不能让负归一化分数造成反向激励。
6. 选中策略连同模型、价格、阈值及提示词哈希封存。正式验证只准入一次；通过后冻结策略，再在考试集执行既定唯一轮次。未准入时照实报告，不声称自进化节省成本。

## 对现有代码的增量改造

- research_agent/model.py：增加提供商适配层，统一 JSON 契约、失败记录、用量归一化与超时；保留已有单模型客户端作为旧运行的回放路径。
- research_agent/roles.py：在角色调用前插入可版本化的 Router；先实现 Qwen-only、固定规则、自进化配置三种模式，不让模型临时改写硬预算。
- evaluation/manifest.py 与 ledger.py：当前 run/1 明确封存单模型，Ledger.llm_call 也拒绝不同模型。新实验必须用新 schema 封存模型目录、各模型价格与路由配置哈希，按每次实际调用模型计价；不得悄悄放宽旧 schema 的审计条件。
- evaluation/self_research.py、report.py、figures.py 与 dashboard：把路由配置作为受限候选，在报告中分列云端调用、代理本地模型用量、总费用、质量、耗时及研究开销。所有展示数字均可追溯到单次调用账本。

## 进入实现前的输入与验收

- 确认赛题允许混合模型，并确认“云端大模型调用情况”的官方统计口径。
- 取得一个可用于 dev 的 Claude API 或 OpenAI API 模型、真实价目及有限预算；凭据仅从环境注入，不能写入仓库或日志。
- 先用模拟传输完成路由、双模型账本、失败计费和旧运行兼容测试，再花真实云端额度做 practice 小试；未经实测不得填报任何节省百分比。

此方案不会替代正在进行的朴素成本校准。优先完成现有校准和弱差距题审计，再决定是否将多模型路由并入正式评估协议。
